# 09_meeting_room_pipeline: 会議室予約（いいとこどり + パイプライン）

## 🎯 この章のねらい
06（契約）・07（関数型）・08（データ指向）を踏まえて、**同じ4要求**を「どこまで簡素で堅牢で保守しやすくできるか」で作り直します。

- 言語は **Python**、テストは **pytest**、性質テストに **hypothesis**
- 標準ライブラリ + `hypothesis` だけ（`icontract` も `jsonschema` も使わない）
- クラスは**データ（`frozen dataclass`）**と**差し替えたい所のインターフェース（`Protocol`）**だけに使う
- 処理は名詞ではなく**動詞**で切り、**ルールの関数を順に通すパイプライン**にする

## 📖 要求（06・07・08 と同じ）

| # | 要求 |
| --- | --- |
| 1 | ユーザーは会議室と時間を指定して、枠を予約できる |
| 2 | 先客がいたら、その枠は取れない |
| 3 | ユーザーは予約を解除して、枠を返却できる |
| 4 | 役員用会議室は、役員以上だけが使える |

設計の考えどころ・4つの章との対比・やってみてわかったことは [DESIGN.md](DESIGN.md) を見てください。

## 🚀 実行方法
```bash
uv run pytest 09_meeting_room_pipeline
```
