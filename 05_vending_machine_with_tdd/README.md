## 📖 お題

お金を入れて、飲み物を買える自動販売機を作ります。

### 業務ルール（叩き台）

| # | ルール |
| --- | --- |
| 1 | 投入できるお金は 10 / 50 / 100 / 500 / 1000 円のみ。それ以外は受け付けず、そのまま返す |
| 2 | 商品は「名前・価格・在庫」を持つ。同じ商品を複数の列（スロット）に入れてもよい |
| 3 | 投入額が価格以上で在庫があれば購入でき、釣り銭を返す |
| 4 | 投入額が足りない／在庫切れのときは購入できない |
| 5 | 釣り銭は**機械内の硬貨の枚数**から払い出す。ちょうど払い出せないときは購入できない（釣り銭切れ） |
| 6 | 払い戻しをすると、投入したお金を返す |
| 7 | ✅【発展】支払い方法を **現金** と **ICカード** で差し替えられる（ICカードは釣り銭なし・残高から引き落とし） |
| 8 | ✅【発展】売上（商品別の販売数・金額）を集計できる |

> ルールは進めながら増減してOKです。決めたことは `DESIGN.md` に反映します。

## 🧭 設計の考えどころ（答えは書きません）

1. **`VendingMachine` に全部書かない**: 「お金の扱い」「商品と在庫」「釣り銭の払い出し」は同じ責務？ 変更理由が違うものは分けてみよう
2. **お金は数字？ 値オブジェクト？**: 不正な金額（例: 7円）を、どこで・どう弾く？
3. **釣り銭の計算はだれの仕事？**: 機械本体か、硬貨の在庫を持つ専用のオブジェクトか。「払い出せない」はどう表す？
4. **支払い方法を増やすとき**: `if (method === "ic")` を散らさずに済む形は？（03のStrategy、または02の継承）
5. **エラーの表現**: 残高不足・在庫切れ・釣り銭切れをどう区別する？
6. **TDDの歩幅**: 次に書くテストは「いちばん小さい失敗」から。仮実装 → 三角測量 → リファクタ。クラスは**テストが分けたがったとき**に分ける
