# 06_meeting_room_contracts: 会議室予約（契約プログラミング）

## 🎯 この章のねらい
**契約による設計（Design by Contract）** を体験します。事前条件・事後条件・不変条件を「どのクラスが誰に約束するか」として設計し、最後は継承で **LSP違反** を体感します。

- 言語は **Python**、テストは **pytest**
- 最初は `assert`、のちに `icontract` へ置き換える
- 使えそうな既習要素: 値オブジェクト・カプセル化（01）／継承・ポリモーフィズム（02）

---

## 📖 要求（4つだけ）

| # | 要求 |
| --- | --- |
| 1 | ユーザーは会議室と時間を指定して、枠を予約できる |
| 2 | 先客がいたら、その会議室と時間の枠は取れない |
| 3 | ユーザーは予約を解除して、枠を返却できる |
| 4 | 役員用会議室は、役員以上だけが使える |

クラス図・契約の置き場所は [DESIGN.md](DESIGN.md) を見てください。

## ⚖️ 失敗は2種類
- **契約違反**はバグ。呼ぶ側の責任で、`assert` で落とす
- **業務上の失敗**（その時間は埋まっている）は普通に起こる

`is_available(slot)` を用意し、「呼ぶ前に確認する」を `reserve` の事前条件にします。

## 🪜 進め方
1. TimeSlot
2. Position・User・Room・Reservation
3. RoomCalendar と reserve / cancel
4. わざと契約を破るテストを書き、ちゃんと落ちるか確かめる
5. `assert` を `icontract` に置き換える
6. 役員用会議室（ExecutiveRoom）を継承で作り、事前条件を強めると LSP 違反になることを体感する
