# 08 設計メモ（06・07 との対比）

## 設計前提
- データは `dict` / `list` / 文字列だけ。クラスも `dataclass` も作らない
- 関数は元のデータを書き換えない。新しいデータを返す
- データの形はスキーマ（これもデータ）で別に定義し、**境界で検証**する
- 失敗は `{"ok": False, "error": ...}` というデータで返す

## 1. データの形

```json
{
  "room": {"name": "役員室", "min_position": "executive"},
  "bookings": [
    {
      "user": {"name": "神田", "position": "executive"},
      "slot": {"start": "2026-11-03T10:00", "end": "2026-11-03T11:00"}
    }
  ]
}
```

- 日時は ISO 8601 の文字列（分まで）。形を固定してあるので、文字列のまま大小比較できる
- 役員室かどうかは `min_position` というデータで表す（`"staff"` なら誰でも使える）
- 役職の強さは `rooms.POSITION_RANK` というデータで持つ

## 2. ファイルの役割

| ファイル | 中身 |
| --- | --- |
| `schemas.py` | データの形（JSON Schema）。`USER` / `SLOT` / `ROOM` / `BOOKING` / `SCHEDULE` |
| `validate.py` | 検証。形はスキーマで、関係は手書きで検査。どれも問題の一覧（空なら問題なし）を返す |
| `slots.py` / `rooms.py` | `overlaps` / `can_use`。データを受け取って判定するだけ |
| `schedules.py` | `new_schedule` / `is_available` / `reserve` / `cancel` |
| `schedule_store.py` | 予約情報の置き場所。JSON 文字列として預かり、読み込み時に検証する |

## 3. 06・07 との対比

| 論点 | 06 (OOP + 契約) | 07 (FP) | 08 (DOP) |
| --- | --- | --- | --- |
| データの表し方 | クラス（状態 + 振る舞い） | `frozen dataclass`（専用の型） | `dict` / `list`（汎用） |
| 役員室 | 継承で上書き | `Access` というデータ | `min_position` というデータ |
| `start < end` | クラス不変条件 | `__post_init__` と `make_slot` | `validate.slot_errors`（スキーマでは言えない） |
| 重複禁止 | 不変条件（全メソッドの前後） | `__post_init__`（作る瞬間） | `validate.schedule_errors`（境界で検査） |
| 失敗の表し方 | 例外（契約違反） | `Ok` / `Err` | `{"ok": False, "error": ...}` |
| 保存 | `RoomCalendar` をそのまま預かる | `Schedule` を預かる | データが JSON そのもの。`json.dumps` / `loads` で済む |
| 不変にする方法 | しない（可変） | `frozen` で言語が保証 | **規律**（書き換えない）。テストで確かめる |

## 4. スキーマで言えること・言えないこと
JSON Schema で言えるのは**形**（項目があるか、型、役職が `staff` / `executive` のどちらか、日時の書式）まで。
次の2つは**複数の要素にまたがる関係**なので、スキーマでは言えず、`validate.py` に手書きしている。

- `start < end`
- 予約同士が重ならない

これは DOP の限界でもあり、「形の検証」と「関係の検証」を分けて考える入り口になる。

## 5. 07 と比べて得たもの・失ったもの

### 得たもの
- **保存・送受信が楽**: データがそのまま JSON。07 の `Schedule` を保存するには変換コードが要る
- **柔軟**: 項目を足しても、使わない関数は影響を受けない
- **スキーマという共通言語**: 形の定義を、実装から切り離してドキュメントや他システムと共有できる

### 失ったもの
- **IDE の補完と静的な型検査**: キーは文字列なので、`"positon"` と打ち間違えても実行するまで気づけない
- **不変性の保証**: Python の `dict` は書き換えられる。「書き換えない」という約束と、テストに頼る
- **不変条件の自動保証**: 07 は `__post_init__` で作る瞬間に守った。08 は「境界で検証する」と決めた場所でしか守れない。`reserve` に渡す前の `schedule` は検証しない、など穴が残る

## 6. 今回やらなかったこと
