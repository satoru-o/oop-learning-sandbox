# 08_meeting_room_data_oriented: 会議室予約（データ指向プログラミング）

## 🎯 この章のねらい
06（OOP + 契約）、07（関数型）と**同じ4要求**を、**データ指向プログラミング（DOP）**で作り直し、3つを並べて見ます。
DOP は Yehonathan Sharvit の本で整理された考え方で、次の4原則を守ります。

| # | 原則 | 08 での姿 |
| --- | --- | --- |
| 1 | コード（振る舞い）とデータを分ける | 関数は `schedules.py` などに、データは `dict` / `list` に |
| 2 | データは汎用のデータ構造で表す | クラスを作らず `dict` / `list` / 文字列だけ |
| 3 | データは不変にする | 関数は元のデータを書き換えず、新しいデータを返す |
| 4 | スキーマをデータ表現から分ける | `schemas.py`（JSON Schema）で形を別に定義し、`validate.py` で検証 |

- 言語は **Python**、テストは **pytest**（06・07 と同条件）
- スキーマ検証に `jsonschema` を使う（`uv add jsonschema` 済み）
- 失敗も例外ではなくデータで返す: `{"ok": False, "error": "overlapped"}`

## 📖 要求（06・07 と同じ）

| # | 要求 |
| --- | --- |
| 1 | ユーザーは会議室と時間を指定して、枠を予約できる |
| 2 | 先客がいたら、その枠は取れない |
| 3 | ユーザーは予約を解除して、枠を返却できる |
| 4 | 役員用会議室は、役員以上だけが使える |

データの形・対比表・トレードオフは [DESIGN.md](DESIGN.md) を見てください。

## 🚀 実行方法
```bash
uv run pytest 08_meeting_room_data_oriented
```
