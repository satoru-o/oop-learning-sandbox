# 04_mini_library_system: 図書館の貸出管理システム（超ミニマム版）

## 🎯 この章のねらい
01〜03で学んだ要素を**自分で設計して組み合わせる**回です。お題は「実際にありそう」な業務システムですが、DB・Web・UIは作りません。**ドメインモデル（業務ルールを持つクラス群）をコードで表現する**ことに集中します。

- 言語は **Python のみ**
- 入出力は不要。`if __name__ == "__main__":` で動作デモが動けばOK
- 使えそうな既習要素: カプセル化・単一責任・コンポジション（01）／継承・ポリモーフィズム（02）／Strategy（03）

---

## 📖 お題

小さな図書館の「本の貸出・返却」を管理するシステムを作ります。

### 登場人物
- **本（Book）**: 蔵書。同じタイトルでも1冊1冊を区別する（コピー単位）
- **会員（Member）**: 本を借りる人。会員種別は `一般` / `学生` の2種類
- **貸出（Loan）**: 「誰が・どの本を・いつ借りて・いつまでに返すか」の記録

### 業務ルール

| # | ルール |
| --- | --- |
| 1 | 貸出中の本は、他の人は借りられない |
| 2 | 同時に借りられる冊数は、一般 **3冊** / 学生 **5冊** まで |
| 3 | 貸出期間は、一般 **14日** / 学生 **21日** |
| 4 | 返却期限を過ぎた場合、延滞日数 × **10円** の延滞料が発生する（学生は **5円**） |
| 5 | 延滞料が未払いの会員は、新しく借りられない |
| 6 | 返却すると、その本は再び貸出可能になる |

> 日付は `datetime.date` を使い、「今日」は外から渡せる形にしておくと延滞のテストがしやすくなります。

## 🧭 設計の考えどころ（答えは書きません）

どこに何を置くかを自分で決めるのが、この章の本題です。

1. **責務の分割**: ルール2〜4を「会員種別ごとの違い」とみなすと、どこに持たせるのが自然？
   `if member.type == "student"` を散らさずに済む形を考えてみよう（02の継承か、03のStrategyか、それとも別の手？）
2. **誰が貸出の可否を判断する？**: `Book` / `Member` / `Loan` / それらを束ねる `Library`（サービス）のどれ？
3. **状態の持ち方**: 「貸出中かどうか」は `Book` のフラグ？ それとも `Loan` の有無から導く？ 二重管理になっていない？
4. **エラーの表現**: 貸出不可の理由（貸出中・上限超過・延滞料未払い）を、01と同様にカスタム例外で区別する
5. **ロジックと表示の分離**: クラス内で `print` しない。結果は戻り値か例外で返す
